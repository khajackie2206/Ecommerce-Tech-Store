## Mục tiêu

Tạo module `users` với entity `User` khớp bảng `Users` có sẵn, và `UsersService` (tạo user, tìm theo email, tìm theo id). Quan trọng nhất: cột `passwordHash` **không bao giờ** xuất hiện trong bất kỳ response nào của API.

Task này chưa có route nào. Nó là nền cho task "Đăng ký và đăng nhập bằng JWT" ngay sau.

**Làm sau:** Phần 3 (đã biết entity, Repository, DTO). Nên làm khi Phần 6 đã merge để ít xung đột ở `app.module.ts`. Bắt đầu bằng `git switch main`, `git pull`, `npm run setup`.

**Đọc trước:** giáo trình Bài 9 (xác thực), phần entity User và ẩn mật khẩu.

## Bảng `Users` trong `database/schema.sql`

| Cột | Kiểu SQL Server | Ghi chú |
|---|---|---|
| `id` | `UNIQUEIDENTIFIER` | GUID, SQL Server tự sinh bằng `NEWSEQUENTIALID()` |
| `email` | `NVARCHAR(255)` | `UNIQUE` |
| `passwordHash` | `NVARCHAR(255)` | chuỗi băm argon2, **không phải** mật khẩu gốc |
| `fullName` | `NVARCHAR(100)` | |
| `phone` | `VARCHAR(20)` | được `NULL` |
| `role` | `VARCHAR(20)` | mặc định `'customer'`, `CHECK` chỉ cho `'customer'` hoặc `'admin'` |
| `isActive` | `BIT` | mặc định `1` (false = tài khoản bị khoá) |
| `createdAt`, `updatedAt` | `DATETIME2` | mặc định `SYSUTCDATETIME()` |

Vì sao `id` là GUID mà không phải số 1, 2, 3 như `Categories`? Id của user sẽ nằm trong token và URL. Số tăng dần thì đoán được ("user 5 có rồi, thử user 6"), GUID thì không.

## Bước 2: Entity

Tạo `src/users/user.entity.ts`:

```ts
import { Exclude } from 'class-transformer';
import {
  Column,
  CreateDateColumn,
  Entity,
  PrimaryGeneratedColumn,
  UpdateDateColumn,
} from 'typeorm';

// The only roles CK_Users_role allows in schema.sql
export const USER_ROLES = ['customer', 'admin'] as const;
export type UserRole = (typeof USER_ROLES)[number];

// Maps to the existing Users table in database/schema.sql
@Entity('Users')
export class User {
  // UNIQUEIDENTIFIER generated by SQL Server (NEWSEQUENTIALID()).
  // A GUID can't be guessed like 1, 2, 3..., so user ids are safe to put in URLs and tokens.
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @Column({ type: 'nvarchar', length: 255, unique: true })
  email: string;

  // Never sent to the client: ClassSerializerInterceptor drops @Exclude() fields
  @Exclude()
  @Column({ type: 'nvarchar', length: 255 })
  passwordHash: string;

  @Column({ type: 'nvarchar', length: 100 })
  fullName: string;

  @Column({ type: 'varchar', length: 20, nullable: true })
  phone: string | null;

  @Column({ type: 'varchar', length: 20, default: 'customer' })
  role: UserRole;

  @Column({ type: 'bit', default: true })
  isActive: boolean;

  @CreateDateColumn({ type: 'datetime2' })
  createdAt: Date;

  @UpdateDateColumn({ type: 'datetime2' })
  updatedAt: Date;
}
```

Giải thích:
- `USER_ROLES = [...] as const` và `UserRole`: `as const` giữ nguyên giá trị chữ, nên `UserRole` là kiểu `'customer' | 'admin'` chứ không phải `string`. Gán `user.role = 'boss'` sẽ báo lỗi ngay khi gõ. Danh sách này khớp với `CK_Users_role` trong database.
- `@PrimaryGeneratedColumn('uuid')`: khoá chính là GUID do database sinh. Kiểu TypeScript là `string`.
- `@Exclude()` (từ `class-transformer`): đánh dấu "đừng đưa field này ra JSON". Tự nó chưa làm gì cả; Bước 4 mới bật cơ chế đọc dấu này.
- `phone: string | null` cùng `type: 'varchar'`: với kiểu union như `string | null`, TypeORM **không tự đoán** được kiểu cột. Thiếu `type`, app khởi động lỗi `DataTypeNotSupportedError` (log hiện "Unable to connect to the database. Retrying..." làm bạn tưởng lỗi kết nối).
- `default: 'customer'`, `default: true`: chỉ là mô tả cho TypeORM. Giá trị mặc định thật nằm ở constraint `DF_Users_...` trong `schema.sql` (ta đang dùng cách SQL-first, `DB_SYNCHRONIZE=false`).

## Bước 3: Service và module

Thay `src/users/users.service.ts`:

```ts
import { Injectable } from '@nestjs/common';
import { InjectRepository } from '@nestjs/typeorm';
import { Repository } from 'typeorm';
import { User } from './user.entity.js';

// Data needed to insert a user. The password is already hashed by the caller (AuthService).
export interface CreateUserData {
  email: string;
  passwordHash: string;
  fullName: string;
  phone?: string;
}

@Injectable()
export class UsersService {
  constructor(
    @InjectRepository(User)
    private readonly usersRepo: Repository<User>,
  ) {}

  // Emails are stored in lowercase, so " An@Mail.com " and "an@mail.com" are the same account
  findByEmail(email: string): Promise<User | null> {
    return this.usersRepo.findOneBy({ email: email.trim().toLowerCase() });
  }

  findById(id: string): Promise<User | null> {
    return this.usersRepo.findOneBy({ id });
  }

  // INSERT INTO Users ... ; role, isActive and dates come from the column defaults
  create(data: CreateUserData): Promise<User> {
    const user = this.usersRepo.create({
      ...data,
      email: data.email.trim().toLowerCase(),
    });
    return this.usersRepo.save(user);
  }
}
```

Thay `src/users/users.module.ts`:

```ts
import { Module } from '@nestjs/common';
import { TypeOrmModule } from '@nestjs/typeorm';
import { User } from './user.entity.js';
import { UsersService } from './users.service.js';

@Module({
  imports: [TypeOrmModule.forFeature([User])],
  providers: [UsersService],
  // Other modules (AuthModule) that import UsersModule can inject UsersService
  exports: [UsersService],
})
export class UsersModule {}
```

Giải thích:
- `CreateUserData` nhận `passwordHash`, **không** nhận `password`. Băm mật khẩu là việc của `AuthService` (task sau). `UsersService` chỉ lo đọc/ghi bảng.
- `email.trim().toLowerCase()` ở cả lúc tạo và lúc tìm: người dùng gõ `An@Mail.com` lúc đăng ký và `an@mail.com` lúc đăng nhập vẫn phải ra cùng một tài khoản.
- `exports: [UsersService]`: mặc định provider chỉ dùng được bên trong module của nó. Export thì module nào `imports: [UsersModule]` (sắp tới là `AuthModule`) mới inject được `UsersService`.

## Bước 4: Bật `ClassSerializerInterceptor` cho toàn app

Interceptor chạy **sau** khi controller trả kết quả và **trước** khi NestJS gửi JSON. `ClassSerializerInterceptor` gọi `instanceToPlain()` của class-transformer lên kết quả, và hàm này bỏ các field có `@Exclude()`.

Trong `src/app.module.ts`:

1. Sửa 2 dòng import:

   ```ts
   import { ClassSerializerInterceptor, Module } from '@nestjs/common';
   import { APP_FILTER, APP_INTERCEPTOR } from '@nestjs/core';
   ```

2. Thêm vào cuối mảng `providers`:

   ```ts
       // App-wide interceptor: runs class-transformer on every response,
       // so fields marked @Exclude() (passwordHash) never leave the server
       { provide: APP_INTERCEPTOR, useClass: ClassSerializerInterceptor },
   ```

Lưu ý: interceptor chỉ xử lý được **instance của class** (`new User()`, hoặc object TypeORM trả về). Nếu bạn tự dựng object thường kiểu `{ email: user.email, passwordHash: user.passwordHash }` thì `@Exclude()` không có tác dụng. Cứ trả nguyên entity là an toàn.

## Bước 5: Test

Tạo `src/users/user.entity.spec.ts`, kiểm tra `@Exclude()` hoạt động, kể cả khi `User` nằm lồng trong object khác (đăng nhập sẽ trả `{ accessToken, user }`):

```ts
import { instanceToPlain } from 'class-transformer';
import { User } from './user.entity.js';

describe('User entity', () => {
  it('drops passwordHash when turned into JSON', () => {
    const user = Object.assign(new User(), {
      email: 'an@mail.com',
      passwordHash: '$argon2id$v=19$...',
      fullName: 'Nguyễn An',
    });

    // instanceToPlain is exactly what ClassSerializerInterceptor runs on responses
    const json = instanceToPlain(user);

    expect(json.email).toBe('an@mail.com');
    expect(json).not.toHaveProperty('passwordHash');
  });

  it('also hides passwordHash when the user is nested in another object', () => {
    const user = Object.assign(new User(), { passwordHash: 'secret' });
    const json = instanceToPlain({ accessToken: 'abc', user });
    expect(json.user).not.toHaveProperty('passwordHash');
  });
});
```

Thay `src/users/users.service.spec.ts` (bản CLI sinh ra sẽ lỗi vì `UsersService` giờ cần Repository):

```ts
import { Test, TestingModule } from '@nestjs/testing';
import { getRepositoryToken } from '@nestjs/typeorm';
import { User } from './user.entity.js';
import { UsersService } from './users.service.js';

describe('UsersService', () => {
  let service: UsersService;
  // Fake repository: only the methods UsersService calls
  const usersRepo = {
    findOneBy: vi.fn(),
    create: vi.fn((data: Partial<User>) => data),
    save: vi.fn((user: Partial<User>) => Promise.resolve(user)),
  };

  beforeEach(async () => {
    vi.clearAllMocks();
    const module: TestingModule = await Test.createTestingModule({
      providers: [
        UsersService,
        { provide: getRepositoryToken(User), useValue: usersRepo },
      ],
    }).compile();

    service = module.get(UsersService);
  });

  it('findByEmail looks up the trimmed, lowercase email', async () => {
    await service.findByEmail('  An@Mail.COM ');
    expect(usersRepo.findOneBy).toHaveBeenCalledWith({ email: 'an@mail.com' });
  });

  it('create stores the email in lowercase', async () => {
    const user = await service.create({
      email: 'An@Mail.com',
      passwordHash: 'hash',
      fullName: 'Nguyễn An',
    });
    expect(user.email).toBe('an@mail.com');
    expect(usersRepo.save).toHaveBeenCalledOnce();
  });
});
```

Tạo `test/users.e2e-spec.ts`, kiểm tra entity khớp bảng thật:

```ts
import { Test, TestingModule } from '@nestjs/testing';
import { INestApplication } from '@nestjs/common';
import { App } from 'supertest/types.js';
import { DataSource } from 'typeorm';
import { AppModule } from './../src/app.module.js';
import { configureApp } from './../src/app.setup.js';
import { User } from './../src/users/user.entity.js';
import { UsersService } from './../src/users/users.service.js';

// Checks that the User entity matches the real Users table (SQL Server must be running)
describe('Users (e2e)', () => {
  let app: INestApplication<App>;
  // A unique email per run, so the test can be repeated without "already exists" errors
  const email = `e2e-${Date.now()}@test.local`;

  beforeAll(async () => {
    const moduleFixture: TestingModule = await Test.createTestingModule({
      imports: [AppModule],
    }).compile();

    app = moduleFixture.createNestApplication();
    configureApp(app);
    await app.init();
  });

  afterAll(async () => {
    // Clean up the row this test inserted
    await app.get(DataSource).getRepository(User).delete({ email });
    await app.close();
  });

  it('creates a user and reads it back with the database defaults', async () => {
    const users = app.get(UsersService);
    const created = await users.create({
      email: email.toUpperCase(),
      passwordHash: 'not-a-real-hash',
      fullName: 'Người Test',
    });

    // Values filled in by SQL Server: GUID id, role/isActive defaults, dates
    expect(created.id).toMatch(/^[0-9A-F-]{36}$/i);
    expect(created.role).toBe('customer');
    expect(created.isActive).toBe(true);
    expect(created.createdAt).toBeInstanceOf(Date);

    const found = await users.findByEmail(email);
    expect(found?.id).toBe(created.id);
    expect(found?.fullName).toBe('Người Test'); // NVARCHAR keeps Vietnamese accents
  });
});
```

- Email có `Date.now()` để mỗi lần chạy là một email mới, không bị trùng `UNIQUE`.
- `afterAll` xoá dòng vừa thêm: test e2e không được để lại rác trong database.
- `toMatch(/^[0-9A-F-]{36}$/i)`: SQL Server trả GUID dạng **chữ hoa**, ví dụ `13B2433E-F36B-1410-89AE-003F495D3012`. Nhớ điều này khi so sánh id với GUID viết thường từ nơi khác.
